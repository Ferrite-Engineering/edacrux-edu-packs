# spi-lab — student handout

SPI is a synchronous serial bus with four signals:

- **SCLK** — clock generated by the master.
- **MOSI** — Master Out / Slave In data line.
- **MISO** — Master In / Slave Out data line. (Held low in this lab —
  the slave does not transmit.)
- **CS_n** — Chip Select, active low. Frames each transfer.

SPI has four modes. They differ in **CPOL** (clock idle polarity) and
**CPHA** (clock phase — which SCLK edge the slave samples on). This
lab uses **mode 0**:

- CPOL = 0 → SCLK idles low.
- CPHA = 0 → master changes MOSI on the falling edge; slave samples
  MOSI on the rising edge.

The master shifts out four bytes — `0x12, 0x34, 0x56, 0x78` — MSB
first, at a 5 MHz SCLK derived from the 50 MHz system clock.

## Part 2 — apply the SPI decoder

1. Right-click on `mosi` (or `sclk`) and choose **Add Decoder → SPI**.
2. WaveCrux loads the binding from `decoders/spi_binding.json` with
   the parameters CPOL=0, CPHA=0, MSB-first, word size 8.
3. Click **Apply**. A new lane appears showing per-transfer brackets
   with the decoded byte values.

## Part 3 — verify with the slave

The slave latches each received byte into `last_byte` when CS_n
returns high. Compare:

- After the *first* CS_n rising edge (t ≈ 1680 ns): `last_byte = 0x__`
- After the *second* (t ≈ 3720 ns): `last_byte = 0x__`
- After the *third* (t ≈ 5760 ns): `last_byte = 0x__`
- After the *fourth* (t ≈ 7800 ns): `last_byte = 0x__`

These should match the decoder's transaction table exactly.
