# Flow fixtures: provenance

One captured LibreLane run of `src/path_adder.v` on the open sky130A PDK with a
2 ns clock, which the flow completes with setup violations. It is real tool
output, copied from the SimCrux open-core LibreLane fixture set
(`verification/fixtures/flow/librelane` in <https://github.com/Ferrite-Engineering/simcrux>,
case `3.0.16/sky130A_timing`, added in commit `115cbb9b`, read at commit
`e0521a5a`; repository licence Apache-2.0, Copyright 2026 Ferrite Engineering
LLC). Only what this pack needs was copied.

## Tools and date

Captured on 2026-10-22 on an Apple M4 Mac mini (darwin arm64), Nix 2.35.3 with
the FOSSi Foundation binary cache, LibreLane 3.0.16 (tag commit
`01ddb25e4424f6f5aaf6b951b14a2b6fdcf737c0`) entered through its own `shell.nix`:
Yosys 0.62 (git `7326bb7d`), OpenROAD `dcf36133a369abc8f3c5e5738cd4d82e4903c0e0`,
KLayout 0.30.7, Magic 8.3.623, Verilator 5.044, ciel 2.4.0.

The PDK is sky130A, standard cells `sky130_fd_sc_hd`, from ciel at open_pdks
commit `8afc8346a57fe1ab7934ba5a6056ea8b43078e71`, the version LibreLane 3.0.16
pins. LibreLane is Apache-2.0, the sky130 PDK is Apache-2.0, Yosys is ISC and
OpenROAD is BSD-3-Clause; none of the tools' licences extends to their output.
The run holds the names of the PDK's cells and layers, not its library, layout
or technology files.

## Command

In LibreLane's Nix shell, in a scratch copy of the design directory with the
configuration `config_timing.yaml` of the source set (the same variables as
this pack's `config.yaml`, with `VERILOG_FILES` pointing beside it instead of
at `src/`):

```
librelane --pdk sky130A --run-tag sky130A_timing config_timing.yaml
```

LibreLane exited with status 2: it completed every step, and its setup-violation
checker raised a deferred error at the end. The verdict of this pack never reads
that status. The SimCrux set trimmed the run with its `tool/flow/trim_run_fixture.py`
(`--keep-corner 'nom_t*'`, home and scratch paths rewritten to `<home>`,
`<design>` and `<run>`); a `config.yaml` re-run with the pack's path was not
made when the pack was assembled.

## Where each expectation comes from

Nothing in `fixtures/expected.json` was generated by SimCrux. The values were
read from the run's own files, then checked again by `tools/edacrux-pack-verify`
on every push, which recomputes each one from those files.

| Expectation | Read from |
|---|---|
| Verdict `violated` | `jq '."timing__setup__ws", ."timing__setup_vio__count"' final/metrics.json`: the worst setup slack is negative and 276 setup violations are counted over all corners |
| `checker-setupviolations` is `failed`, the steps around it `completed` | `ls 72-checker-setupviolations` shows `config.json` and `state_in.json` but no `state_out.json` or `runtime.txt`; `ls 73-checker-holdviolations` and the later directories hold both; `flow.log` has a `Running` line for each of them |
| `yosys-synthesis`, `openroad-stapostpnr`, `misc-reportmanufacturability` are `completed` | each directory holds `state_out.json` |
| Worst setup slack between -6.0 and -1.0 ns | `jq '."timing__setup__ws"' final/metrics.json` reads -3.43 (the `max_ss_100C_1v60` corner); the nominal typical corner's is -0.90 |
| Hold, routing DRC, Magic DRC and LVS counts are 0 | `jq` on `timing__hold_vio__count`, `route__drc_errors`, `magic__drc_error__count`, `design__lvs_error__count` in `final/metrics.json` |
| 73 flip-flops | `jq '."design__instance__count__class:sequential_cell"' final/metrics.json`; by hand from the RTL, 24 + 24 + 25 |
| Worst path starts at `_354_`, ends at `_400_`, violated | the first block of `55-openroad-stapostpnr/nom_tt_025C_1v80/max.rpt`: `Startpoint:`, `Endpoint:` and `-0.903735 slack (VIOLATED)` |
| `_354_` outputs `src_b[1]`, `_400_` outputs `sum_q[23]` | `grep -A4 ' _354_ ('` and `' _400_ ('` on `06-yosys-synthesis/path_adder.nl.v` (the `.Q(...)` net); pinned by `tools/tests/test_flow_state.py` |

The nominal typical corner's listing is the one checkpointed because it is the
corner LibreLane's setup checker selects (`TIMING_VIOLATION_CORNERS` is
`["*tt*"]` in `resolved.json`) and the one listing this pack keeps. The slack
and the count of violating endpoints move with every tool build, so no
expectation pins a measured value.
